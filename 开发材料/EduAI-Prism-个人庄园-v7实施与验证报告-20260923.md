## 3. 实际使用链路

### 教师与学生

1. 教师进入“庄园学习证据”，确认学生学段，选择模板、范围、资源与数据版本、奖励政策后发布。
2. 学生从首页或活动页进入相同正式任务，不生成副本；示例练习单独呈现。
3. 学生保存作答、查看规则反馈、完成表达、修订、反思与复习安排。
4. 教师对具体表达版本评价；被接受的原始内容保持不可变。修改另开新版本或新轮次。
5. 工坊继续编辑同一草稿，明确“另存副本”。发生版本冲突时保留输入，由用户确认后重试。
6. 项目必须引用同一发布/数据版本下三学科已接受的必要贡献；未齐可存草稿，齐全可形成共同成果。

“必要贡献齐全”与“教师认为综合成果达标”是两个不同判断。当前共同成果保持 `evaluationStatus=not_reviewed`，不会额外发奖或自动进入已评价成果。

### 学习到场景

```text
正式发布版本 → taskRun → 作答/表达 → 规则或教师评价 → 学习作品版本
                                      ↓ 独立奖励政策
                                    grant
                                      ↓ 全额消费明细
                                照料动作 → 种植周期 → 收获

已获得积分 → 兑换事务 → 库存实例 → 布置预览 → 服务端保存 → 场景
当前班籍 + 本次公开同意 → 同班只读参观 → 随时撤回
```

积分不等于成长能量；点击、停留、动画或收获不等于学科掌握。保存作品、反思和复习免费。无付费、抽奖、偷取、离线枯萎、个人成绩排名或连续签到惩罚。

## 5. 接口与一致性

| 接口 | 用途 | 关键约束 |
|---|---|---|
| `GET /api/v2/manor/bootstrap` | 庄园当前学习与场景投影 | 当前学生权限，no-store |
| `GET /api/v2/manor/assignments` | 首页/活动共享正式任务 | 只读同一发布实例 |
| `POST /api/v2/teacher/manor/assignments` | 教师发布 | 当前教师/班级、学段、幂等编号、版本快照 |
| `POST /api/v2/manor/task-runs` | 学习阶段与新轮次 | revision 并发校验 |
| `POST /api/v2/manor/artifacts` | 创建或更新作品 | 同一草稿 ID、期望版本、已接受版本不可变 |
| `POST /api/v2/manor/projects/{id}` | 保存共同成果 | draft/complete 分开，引用版本与必要贡献校验 |
| `GET /api/v2/manor/plots/{id}/history` | 完整种植来源 | 每页默认 10，最大 50；游标绑定用户/地块 |
| `GET/POST /api/v2/manor/scene` | 库存、交易、布局、公开 | 价格服务器决定；扣分入库同事务；布局 CAS；账号与班级一致 |
| `GET /api/v2/manor/scene?visit=...` | 公开参观 | 同班、自愿公开、字段白名单 |
| `GET /api/v2/manor/operations/{id}` | 结果未知时恢复 | 只读本人回执；公开名单取当前状态 |
| `GET/POST /api/v2/teacher/manor/scene-policy` | 班级开放区域 | 当前教师/班级，10～24，修订版本，只增不减 |

旧 `POST /api/manor` 保持 410，不重新启用绕过学习证据校验的写通道。

### 关键边界修复

1. 兑换已提交但响应丢失时，重用原 operationId 查回执，不重新扣分。
2. A 账号待确认操作切到 B 时，不删除 A 的恢复记录；回到 A 可恢复同一操作。
3. 公开同意绑定用户当时看到的班级，转班后旧命令不能自动向新班级公开。
4. 舒缓模式仍可撤回公开，不能把健康节奏变成隐私操作障碍。
5. 旧参观接口与回执不能重新暴露已经撤回的伙伴名单。
6. 布局占位、所有权、库存、余额、版本都由服务器重新检查。

## 8. 本地与互联网使用边界

当前仍为 Next.js + React + TypeScript + Node SQLite 架构，使用现有登录与请求防护。迁移新增表/列，不清空历史数据。启动前已创建一致性数据库备份，存放在本机忽略版本控制的 `.data-backup` 中。

### 学校本地

- 同校单实例、持久磁盘、反向代理、学校身份管理与定期备份；内网中也需要 HTTPS、权限和日志脱敏。
- 启动命令可直接调用 Node，避免把机器 PowerShell 策略全局改成无限制。
- 本轮留在 `127.0.0.1`，不开放公网防火墙，也不假设校内其他电脑已经能访问。
- 备份必须覆盖业务数据库与其他上传资料，并做恢复演练；本轮备份成功不是恢复演练完成。

### 互联网

- 可沿用单校单实例部署，前置 HTTPS，配置持久卷、访问频控、备份与监控。
- SQLite 不放临时/易失文件系统；不将多实例共享 SQLite 文件当成已验证的扩容方案。
- 当前用户模型缺独立 schoolId 租户域；多个学校进入同一实例前必须新增学校隔离、迁移与越权测试，不能只依赖 classId。
- 本轮未向互联网发布，未验证真实 Docker 容器、远程学校网络、CDN 缓存或外部登录集成。

## 9. 后续工作及验收条件

1. 对证据、作品、复习、旧任务历史补全面分页与按需读取；在长周期账户、低带宽和高并发下实测，不先宣称速度提升倍数。
2. 将温室/工坊从环境图独立拆出并做遮挡、缩放、焦点与弱机性能复验。当前具名热点是可用实现，不是独立建筑动画完成。
3. 如需“综合项目教师总评”，新增总评量规、待审队列、意见与修订版本；不把三个学科通过简单加总成跨学科能力分。
4. 校内资源文件版本与任务快照建立不可变引用；删除/撤回文件时保留最小审计信息并显示真实缺失原因。
5. 分别做学校内网、互联网单校部署和恢复演练；多校实例须先完成租户隔离。
6. 教师审核学段适配后开展小范围试点，记录完成率、求助方式、误解、可访问性和认知负担。真实教学成效不能由软件单测证明。
