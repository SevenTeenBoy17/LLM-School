> 版本：2.0  
> 日期：2026-08-23  
> 页面：`/student/manor`  
> 基准：桌面端 `1440 × 900`  
> 边界：纯前端、本地模拟数据、不新增或调用庄园后端

## 1. 交付结论

本轮已将学生端“个人庄园”重建为可运行、可维护的 Next.js 页面。界面采用经典 QQ 农场的空间语法：完整农场场景、斜向土地阵列、木质资源 HUD、顶部玩法入口、左侧活动入口、好友坞、仓库与工具栏。页面不是截图壳，所有主要可见按钮、地块操作、弹窗、下拉菜单和异常状态均可交互。

实现严格限定为前端复刻：庄园页面不调用 `/api/manor`，不访问外部网络，不使用 `localStorage`、`sessionStorage` 或 IndexedDB，不新增数据库、API Route、Server Action、WebSocket、上传或付费逻辑。项目中原有的庄园 API 文件不属于本轮实现，页面也不会访问它。

## 3. 视觉结构

### 3.1 顶部微客户端层

- 第一行：返回、产品标识、`QQ农场 / 成长花园 / 应用中心` 标签、设置、帮助、用户菜单。
- 第二行：在线状态、农场首页、装扮农场、农场图鉴、好友列表、问题反馈和服务器信息。
- 标签、用户菜单和状态预览均为真实可操作控件，不是装饰文字。

### 3.2 主场景层

- 全屏农场位图覆盖可视区域，场景不被卡片容器切碎。
- 左上为木质玩家 HUD，显示等级、经验、金币和累计收获。
- 天气组件与 HUD 并列，避免遮挡中央田地。
- 右上四个玩法入口分别为牧场、时光农场、节气系统和锁定的魔法池。
- 左侧四个活动入口带通知角标；文字固定单行，不发生断裂或挤压。
- 中央为 24 块土地，沿原场景透视方向排列，包含作物、虫害、忙碌、成熟和锁定状态。
- 底部为好友坞；右下为仓库及六项农具，所有高频操作保持常驻。

### 3.3 视觉语言

- 木色、米白纸面、麦黄色高光与草地绿色共同构成农场语义，不使用单一蓝紫后台主题。
- 主要按钮保持至少 `44 × 44px` 命中区。
- 模态窗口采用木框与纸面组合，和场景 HUD 保持同一材质体系。
- 动画用于作物摆动、加载、弹窗和提示反馈；`prefers-reduced-motion` 下关闭非必要动画。

## 4. 交互合同

### 4.1 地块与工具

| 操作 | 前置状态 | 可见结果 |
|---|---|---|
| 播种 | 已解锁空地 | 打开种子面板，选择番茄后地块立即显示作物 |
| 浇水 | 已种植且未成熟 | 进入短暂忙碌态，完成后显示成功提示 |
| 除虫 | 存在虫害 | 清除虫害标识并显示结果 |
| 施肥 | 已种植且未成熟 | 推进本地模拟成长并显示结果 |
| 铲除 | 已种植地块 | 地块恢复为空地 |
| 收获 | 成熟地块 | 作物清空，金币增加 86，累计收获增加 1 |

所有结果都在等待模拟操作完成后再反馈；不会在操作尚未完成时提前声称成功。

### 4.2 导航与弹层

- 顶部标签可切换选中状态。
- 用户头像可打开/关闭账户菜单。
- 状态预览下拉可切换正常、加载、失败、空和禁用场景。
- 四种玩法、四项活动、四个建筑热点、仓库和空地播种均有对应弹窗或面板。
- `Escape` 可关闭当前弹层，遮罩区域可关闭模态窗口。
- 魔法池、锁定地块和禁用态工具会给出明确不可用原因。

## 5. 状态覆盖

| 状态 | 呈现方式 | 验收点 |
|---|---|---|
| 正常 | 完整场景和操作控件 | 24 地块、6 工具、资源 HUD 正常 |
| 加载 | 场景内加载覆盖层 | 不改变整体布局尺寸 |
| 失败 | 错误说明与重新加载按钮 | 点击后恢复正常场景 |
| 空状态 | 空农场说明 | 仍保留全局导航和可恢复路径 |
| 禁用 | 暂停说明与禁用工具 | 控件真实 `disabled`，不是仅变灰 |
| 锁定 | 锁图标与等级说明 | 不执行地块操作 |
| 忙碌 | 单地块处理中 | 等待完成后才返回结果 |
| 成熟/虫害 | 地块内直观标识 | 可由对应工具完成操作 |

## 6. 前端实现

### 6.1 组件划分

- `FarmChrome`：双层顶部导航、标签、用户与状态菜单。
- `PlayerStatusPanel`：等级和资源 HUD。
- `ModeDock`：四种玩法入口及锁定态。
- `ActivityRail`：活动入口和通知状态。
- `CropPlant` 与地块网格：24 地块及作物阶段。
- 建筑热点、好友坞、仓库、工具栏、状态覆盖层、模态窗口和 Toast。

页面使用 `createPortal(..., document.body)` 将农场舞台固定到浏览器视口，避免父级应用壳的 transform 影响 `position: fixed`。客户端挂载通过 `useSyncExternalStore` 区分服务端快照与浏览器快照，避免 hydration 不一致及 effect 内同步 setState。

### 6.2 数据模型

- 初始地块、作物、活动、好友和玩法均为模块内确定性常量。
- 操作结果只写入当前 React 组件状态，刷新页面后恢复初始演示数据。
- 不读取或保存真实用户信息，不把前端演示状态写入浏览器存储。

## 9. 问题与修复记录

1. 初次视觉测试发现舞台受应用壳 transform 影响，起点偏移至 `(244, 56)`；改为 document body portal 后恢复为 `(0, 0)`。
2. 左侧活动入口宽度不足导致四字标题断行；宽度调整并固定单行后复验通过。
3. 多轮交互后的瞬时提示残留在最终截图；测试现在等待提示完整退场并断言 Toast 数量为 0。
4. React Lint 发现 effect 内同步设置 mounted；改为 `useSyncExternalStore` 后目标 Lint 清零，并再次通过交互验收。
5. 代码关系图可解析目标页面，但对未提交文件和共享 `package.json` 的影响半径产生无关扩散，因此只作为辅助信息，不替代限定范围静态审阅和 Playwright 证据。
