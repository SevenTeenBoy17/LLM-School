# EduAI-Prism 真实公司级内测纠偏协议 v2

日期：2026-07-08 PDT  
适用范围：后续所有前端、后端、AI、权限、导出、移动端与管理端内测轮次。

## 1. 核心纠偏结论

现有内测不得再把“页面能打开、按钮能点、接口返回 200、构建通过”当成产品质量结论。这些只能证明基础健康，不能证明真实用户愿意继续使用。

后续每轮内测必须模拟真实学校或真实公司的使用方式：明确角色、明确业务任务、通过可见 UI 或真实 API 完成任务，等待页面、接口、AI 生成、下载、状态变更、持久化读回全部完成后，才允许进入评价和评判。

未等完整结果返回前，禁止写“通过”“失败”“体验好/差”等结论。此时只能记录“进行中”“等待中”或“证据不足”。

## 2. 真实内测必须包含的 6 个动作

| 阶段 | 必做动作 | 证据 | 未满足时的处理 |
| --- | --- | --- | --- |
| 1. 真实身份 | 使用学生、教师、管理员、研究员等真实角色登录或建立会话 | 角色、账号、入口、当前 URL、可见身份信息 | 不评价角色体验 |
| 2. 真实任务 | 使用真实学校/公司业务任务，不用随机点按钮代替 | 输入内容、业务背景、目标产出、关联页面 | 只能算控件巡检 |
| 3. 完整等待 | 等待 UI/API/AI/下载/保存/发布/审计全部返回 | 开始时间、完成时间、最终内容或状态 | 不得提前判断 |
| 4. 内容复核 | 阅读返回内容本身，判断是否可用于下一步工作 | 关键字段、正文质量、权限、安全、异常提示 | 不得写质量结论 |
| 5. 内部研讨 | 以真实内测会方式，从用户、运营、技术、治理视角讨论 | 结论、取舍、严重度、留存影响 | 不进入修复优先级 |
| 6. 修复复测 | 对确认问题做最小安全修复，重新走完整任务链 | 复测日志、截图/API读回、构建/类型/图谱审阅 | 不标记为完成 |

## 3. 判定口径

可以作为“基础健康证据”的内容：

- HTTP 200、按钮可见、控件 enabled/disabled。
- `lint`、`typecheck`、`build` 通过。
- 静态截图、路由枚举、DOM 可见性。
- 单点 API 成功返回。

可以作为“真实体验证据”的内容：

- 真实角色完成了完整业务目标。
- 生成内容或返回数据已经完整出现，并被读过。
- 结果能被教师、学生、管理员或机构内部会议继续使用。
- 失败、慢响应、降级、权限拒绝、空状态都有诚实反馈。
- 权限、安全、审计、持久化读回与角色预期一致。

## 4. AI 功能特殊规则

AI 场景必须等到最终助手回复、来源、耗时、安全判定和服务端持久化读回完成后再评价。

如果 AI 仍在生成、接口仍在 loading、降级还没显示、会话还没写回，不允许评判内容质量。可以记录等待时长和用户留存风险，但不能把半成品当成结果。

## 5. 内部研讨评价维度

每轮真实使用后必须从四个角度形成结论：

- 用户视角：真实教师/学生/管理员能否顺利完成任务，是否愿意继续使用。
- 运营视角：能否支撑校内推广、培训、复盘、留存与问题定位。
- 技术视角：接口、持久化、权限、错误、性能和降级是否可信。
- 治理视角：安全、审计、合规、误用边界和角色隔离是否可追踪。

## 6. 报告最低字段

每轮报告必须包含：

1. 真实背景与角色分工。
2. 实际操作路径。
3. 等待条件与完成时间。
4. 完整返回结果摘要。
5. 内部研讨结论。
6. 问题清单、严重度、复现路径。
7. 修复方案与已执行修复。
8. 复测证据。
9. 残余风险与下一轮优先级。

## 7. 禁止事项

- 禁止在 AI 仍生成、接口仍 loading、保存/发布/下载未完成时评价质量。
- 禁止用静态截图替代真实业务完成证据。
- 禁止只从开发者角度判断；必须包含真实用户和机构运营视角。
- 禁止只列问题不修复；可安全修复的问题必须修复并复测。
- 禁止把未实现能力包装成已实现；未开通或示例数据必须诚实标注。

## 8. R24 后续执行要求

从 R24 起，提示词、智能体、知识库、聊天、管理后台、移动端等所有后续切片均按本协议执行。静态检查继续保留，但只能作为基础健康门槛；真实产品结论必须来自完整使用链路与内部研讨。
