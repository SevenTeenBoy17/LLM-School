# EduAI-Prism 真实公司级内测纠偏协议

更新时间：2026-07-08

## 1. 本次纠偏结论

后续内测不能再以「页面能打开、按钮能点击、接口返回 200」作为产品体验结论。上述内容只能作为基础健康证据。

真实内测必须模拟真实学校/公司内部使用：由明确角色进入真实业务场景，完成真实任务，等待全部页面、接口、AI 生成、下载或状态变更返回后，再进入内部研讨和评价。未等结果完整返回，不允许写「通过」「失败」或「体验好/差」。

## 2. 真实内测五步法

| 步骤 | 必做动作 | 证据要求 | 未满足时的判定 |
| --- | --- | --- | --- |
| 1. 真实身份 | 使用学生、教师、管理员、研究员等真实角色登录 | 记录账号角色、进入页面、当前 URL、可见身份信息 | 不能评价角色体验 |
| 2. 真实任务 | 使用真实学校/机构任务，而不是随意点按钮 | 记录业务背景、输入内容、预期产出、相关页面 | 只能算控件巡检 |
| 3. 完整等待 | 等待页面、API、AI 回复、下载、状态变更全部完成 | 记录开始时间、完成时间、最终 UI/API/文件内容 | 不得提前判断 |
| 4. 复核读取 | 读取返回内容本身，而不是只看有无返回 | 记录关键字段、正文质量、留痕、权限、错误提示 | 不能写质量结论 |
| 5. 内部研讨 | 以真实公司/学校评审会方式讨论是否能用于工作 | 形成用户视角、运营视角、技术视角、治理视角结论 | 不能进入修复闭环 |

## 3. 评价口径

### 3.1 可以作为「基础健康」的证据

- 页面 HTTP 200
- 控件可见
- 按钮 enabled / disabled 状态
- 接口返回成功码
- lint、typecheck、build 通过

### 3.2 才能作为「真实体验」的证据

- 用户完成了一个真实业务目标
- 返回内容完整、可读、可用于下一步工作
- 权限、留痕、安全策略与角色预期一致
- 失败、慢响应、降级、空状态有诚实提示
- 结果可被教师、管理员或机构内部会议复核

## 4. 本轮优先真实场景

场景名称：初中校内 AI 学习平台学术诚信事件与治理复盘。

参与角色：

- 学生：以学生身份尝试请求 AI 直接完成作业答案。
- 教师：复核学生侧返回内容是否能形成学习引导，而不是代写。
- 管理员：查看安全审计、工单、权限与导出能力是否能支持校内治理。
- 内测评审会：从用户留存、教学可用性、治理可追踪性、产品诚实性四个角度判断。

通过条件：

- 学生侧必须等待 AI/策略回复完整返回，并读取最终回复内容。
- 后端必须能查到对应持久化或治理数据。
- 管理员侧必须等待审计/工单列表真实加载完成后再评价。
- 如涉及导出，必须验证下载文件或导出数据内容，而不是只验证按钮点击。
- 任何慢响应、无反馈、无法追踪、空状态误导，都必须进入问题清单。

## 5. 报告格式要求

每轮报告必须包含：

1. 真实背景与角色分工。
2. 实际操作路径。
3. 等待条件与完成时间。
4. 完整返回结果摘要。
5. 内部研讨结论。
6. 问题清单、严重程度、复现路径。
7. 修复方案与已执行修复。
8. 复测证据。

## 6. 禁止项

- 禁止在 AI 仍在生成、接口仍在 loading、下载未完成时评价质量。
- 禁止把静态截图当作真实业务完成证据。
- 禁止只从开发者视角判断，必须包含真实用户与机构运营视角。
- 禁止只列问题不修复；若可安全修复，必须修复并复测。
- 禁止把未实现能力包装成已实现；未开通或样例数据必须诚实标注。
