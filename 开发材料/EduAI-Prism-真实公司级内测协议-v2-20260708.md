# EduAI-Prism 真实公司级内测协议 v2

适用范围：12小时前后端真实内测、自我迭代、问题复测、内部研讨评审。

## 1. 核心纠偏

之前的路线检查、按钮检查、接口状态码、静态截图，只能作为“系统健康预检”。它们不能直接得出“产品好用”“用户会留存”“功能闭环”的结论。

从本协议开始，每个产品判断都必须来自真实角色完成真实任务后的完整证据链：

1. 明确真实角色：学生、教师、教务/管理员、研究员、校领导、产品运营。
2. 明确真实业务目标：例如备课、家校沟通、学生安全干预、权限治理、提示词发布、资料导出。
3. 通过可见界面或等价的已登录会话真实使用，不只点按钮或扫 DOM。
4. 等待所有 UI、API、AI、保存、导出、下载、回读结果返回。
5. 阅读返回内容本身，检查是否满足真实学校/公司的业务可用性。
6. 做内部研讨式判断：用户能否完成任务、是否愿意复用、是否有风险、是否需要优化。

## 2. 每轮内测必须记录的证据

- 角色与账号：使用哪个真实角色视角，为什么这个角色会做这件事。
- 场景背景：发生在学校/公司里的哪一个真实流程。
- 任务描述：用户真正想完成什么，而不是“测试某按钮”。
- 操作路径：从登录到完成的主要界面路径。
- 等待条件：什么时候才算结果完整返回。
- 返回内容：AI答案、表格、保存状态、导出反馈、API回读或持久化结果。
- 内容阅读结论：返回内容是否准确、完整、可执行、符合教育场景安全边界。
- 内部研讨结论：教师/学生/管理员/产品运营分别会怎样评价。
- 问题清单：只记录真实使用中阻碍任务、误导判断、降低留存或造成风险的问题。
- 复测证据：修复后必须再次执行同一真实任务链路，而不是只跑静态检查。

## 3. 等待与评判规则

AI 生成类任务：

- 必须等待生成状态结束，或 API 返回最终响应。
- 必须记录 `source`、`durationMs` 或 UI 上可见的来源/耗时。
- 必须阅读最新一条有效回答，不允许用历史消息、侧边栏摘要或半截生成内容评判。
- 如果网关降级，需要评估等待时长、降级提示、内容质量和用户留存风险。

保存/发布/权限类任务：

- 必须等待可见成功/失败反馈。
- 必须用服务端回读、重新打开页面、跨角色访问或审计日志证明状态已生效。
- 修改演示账号或权限后必须恢复原状，恢复也要有回读证据。

导出/下载类任务：

- 必须等待产品可见反馈。
- 能捕获文件时检查文件大小、类型、内容片段；浏览器下载能力受限时，必须记录降级原因，并用导出内容/API/状态提示作为替代证据。

后台治理类任务：

- 管理员必须处理真实工单、真实审计记录或真实权限状态。
- 样例区、禁用按钮、静态卡片只能作为展示，不可作为“功能已完成”的证据。

## 4. 内部研讨评分

每条真实链路完成后，从四个维度评分：

- 任务完成度：用户是否无需外部帮助即可完成目标。
- 内容可用度：返回内容是否能直接进入教学、管理、研究或沟通场景。
- 信任与安全：是否诚实展示来源、降级、权限边界、风险提醒。
- 留存影响：用户下次是否愿意继续使用，哪里会让用户放弃。

评分不是为了凑分，而是为了定位下一轮最值得修的真实问题。

## 5. 禁止事项

- 禁止把 `200 OK` 当作产品通过。
- 禁止只看按钮存在就认为功能可用。
- 禁止在 AI 内容未完整返回前评价质量。
- 禁止只测试管理员视角而推断学生/教师也可用。
- 禁止用截图美观替代真实可完成任务。
- 禁止为了通过内测而跳过等待、回读、内容阅读和复测。

## 6. R27 起执行口径

本轮及后续所有内测报告必须写明：

> 本结论来自真实角色完成真实业务任务，并在全部 UI/API/AI/保存/导出结果返回、内容被阅读后，再进行内部研讨式判断。

若某一项证据因工具能力缺失无法采集，必须标记为“降级证据”，说明限制和替代验证方式，不能写成无条件通过。
