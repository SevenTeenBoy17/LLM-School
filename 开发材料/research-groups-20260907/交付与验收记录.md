# 教研组圆桌与成员任务

## 入口与使用

[打开集体备课](http://127.0.0.1:4921/research/prep)，选择“教研组”。本轮仅替换这个标签的内容，其他共备标签仍维持原有本机演示流程。

1. 教师创建私有教研组，填写组名和学科，创建者成为组长。
2. 组长打开“邀请教师”，将邀请码提供给需要加入的教师。教师使用自己的账号登录后，在“加入教研组”粘贴邀请码。
3. 服务端随机分配 BOT，优先使用本组尚未使用的形象；刷新、重新登录、退出后重新加入均保留原形象。教师全名来自账号记录。
4. 组长通过“分配任务”设置负责人、截止日期和检查项。悬停或键盘聚焦 BOT 显示“查看任务”，点击后打开居中弹窗；手机直接点击成员行。
5. 负责人或组长勾选检查项，点击“保存进度”。未保存勾选不计入进度；所有组员可查看，但不能修改他人任务。
6. 同一任务被他人更新时，旧版本提交返回冲突；界面保留当前勾选，必须核对后载入最新版本，不静默覆盖。

## 真实数据边界

- 新增独立 `rg_groups / rg_members / rg_tasks` SQLite 表，与现有账号关联；不修改现有教学数据结构，不写入测试教师到日常数据库。
- 当前窗口可见且激活时约每 3 秒拉取真实快照，重新聚焦立即同步。显示最近成功时间、同步失败和重试，不宣称 WebSocket 推送或实时在线状态。
- 进度 = 已完成检查项 / 已分配检查项。它不是教学质量评分，不使用模拟计时增长。
- 学生无权访问；演示会话只读；每个请求重新校验账号角色、会话版本和组成员关系。邀请码只对真实组长会话返回。
- 更新邀请码使旧码失效。非组长可退出；既有任务和 BOT 记录保留。当前版本不支持转交组长或组长退出。
- 上限：每位教师 20 个组、每组 64 位成员、200 项任务，每任务 16 个检查项。圆桌每页 8 人。
- 没有外部 AI 调用接收教师姓名或任务内容。圆桌图片是制作阶段生成的公共视觉资产。
- 提交结果因网络中断而不确定时，界面要求同步核对后再继续，不能保证刷新页面后的请求幂等恢复。
- 未保存勾选仅保存在当前组件内存；弹窗关闭有确认，但刷新、页面卸载或身份变化后不保证恢复。取消网络请求也不等于撤销服务端已经提交的操作。
