# 校内资源库：前端交付与双部署技术路线

版本：1.0 · 2026-09-08 · 适用范围：教师端、教研员端

> 本轮交付是可实际操作的前端体验，不是已上线的校内共享服务。文件保存到浏览器 IndexedDB；没有新增资源上传 API、数据库表或远程存储连接。未来方案均在下文单独标识。

## 1. 入口与定位

**主入口：教学 → 校内资源库**，位于“知识库”之后。**次入口：知识库页顶部“校内资源库”按钮**。地址 `/knowledge/resources`。

| 工作区 | 主要用途 | 本轮关系 |
|---|---|---|
| 知识库 | 检索资料、为 AI 回答提供来源 | 保留现有行为，不复用其上传 API |
| 校内资源库 | 整理课件、教案、学习单及教学素材 | 新增独立前端，学校共享连接暂不启用 |
| 集体备课 | 讨论、形成备课过程与成果 | 详情提供工作区链接，不声称自动导入 |
| 课件工坊 | 制作课件 | 详情提供工作区链接，未来按版本引用资源 |
| 学生资料 | 教师向班级发布的学习内容 | 本轮不改变；教师同事共享不自动等于向学生发布 |

服务端页面仅允许 `teacher`、`researcher`，未登录跳转登录页，其他角色返回其首页。导航可见性与页面判断使用同一个角色函数。此角色门槛**不是学校租户权限实现**。

## 2. 侧栏留白修复

原展开态使用自动顶开账户区的弹性留白，内容较少时，在导航末尾与账户之间形成大块空白。现改为内容驱动排列，账户紧随导航，保留固定的小间距。

- 侧栏高度限定当前可视窗口；头部和账户区不收缩。
- 屏幕较矮、分组全部展开时，仅中间导航滚动，账户仍可到达。
- 图标坞收起模式保留原有布局；宽度拖动、复位、分组折叠和账户菜单不被替换。
- 不向侧栏塞入无关广告、推荐卡片或虚假统计填充空间。

## 3. 视觉与资产

保持现有教师端字体、全局顶栏、浅色背景和蓝色导航选中态。资源工作区使用**克制的青绿强调色**；珊瑚色课件板、蓝色教案本、琥珀色文件夹区分资源类型，同时保留文字标签，不只依赖颜色。

页面采用紧凑、可扫描的表格为默认视图，提供网格切换。分类、检索和结果是连续页面区域，不使用多层浮动卡片。新增重复资源卡片、弹窗圆角为 8px。常用按钮为稳定尺寸；图标操作具有可读名称与悬停提示；支持键盘焦点及减少动态效果偏好。

窄屏弹窗为全局“安全求助”入口保留空间；极矮横屏（宽度不超过 1100px、高度不超过 360px）使用整窗纵向滚动，让授权选项、保存、下载和关闭操作仍可到达。正常手机与桌面仍使用固定弹窗头尾、中间内容独立滚动。

GPT 生成了六枚独立视觉资产：资料柜、上传托盘、课件展示板、教案本、学习单、文件夹。生成过程先制作材质图，再修正为纯绿色背景；通过色键去绿、边缘去溢色和内容裁切输出透明 WebP。功能按钮仍使用真正的 HTML 控件，不能把表单和按钮文字烘焙进图片。

| 项目 | 交付位置 / 说明 |
|---|---|
| 绿底源图 | `app/public/art/school-resources/source-atlas.png` |
| 图标 | 同目录六个 `.webp`，每个 320 × 320 |
| 原图实际尺寸 | 1536 × 1024；不冒称 4K 或无损放大的超高清原图 |
| 校验与生成说明 | 同目录 `manifest.json`，含源图和各图标 SHA-256 |
| 可重复处理 | `node scripts/build-school-resource-assets.mjs <批准的源图路径>` |
| 组件 | `app/components/common/SchoolResourceIcon.tsx` |

视觉主资产均为本轮 GPT 生成，没有上传教师文件去生图，没有嵌入 API 密钥，没有引入运行时图片生成依赖。图标随应用静态部署，在内网可加载。

## 4. 已实现的交互闭环

```text
进入资源库 → 浏览 / 搜索 / 组合筛选 → 查看详情 → 收藏或下载
                     ↓
选择真实文件 → 格式与容量校验 → 填写学科年级 → 本机保存授权
                     ↓
SHA-256 校验 → IndexedDB 事务提交成功 → 我的草稿
                     ↓
刷新后恢复 → 原文件下载 / 编辑资料 → 再保存或确认移除
```

| 控件 / 状态 | 真实行为 | 失败或边界 |
|---|---|---|
| 类型、学科、年级、关键词 | 组合过滤当前示例与本机草稿 | 明确无结果并可清空筛选 |
| 全部 / 我的草稿 / 我的收藏 | 切换集合、显示真实本机数量 | 无内容显示对应空态 |
| 列表 / 网格 | 同一数据集合两种布局 | 收藏状态一致 |
| 收藏 | 写入当前账户命名空间的 IndexedDB | 提交失败不展示成功结果 |
| 上传资源 | 打开选择 / 拖拽、队列及元数据表单 | 无伪造网络上传进度 |
| 保存本机草稿 | 文件字节、SHA-256 和元数据实际保存 | 等事务完成才关闭窗口并提示成功 |
| 编辑信息 | 更改标题、类型、学科、年级、简介、分享意向和来源声明 | 保留原文件；重新确认本机保存 |
| 下载示例提纲 | 导出真实 Markdown 示例教学提纲 | 明确不是原始 PPT、Word 或真实校内共享文件 |
| 下载原文件 | 导出本机保存的文件 Blob | 原始字节不经 AI 改写 |
| 预览 | TXT / MD 按纯文本展示；PNG / JPG / WebP 图片展示 | Office / PDF 暂展示元数据和下载，不假装转换成功 |
| 取消 / 关闭 | 无修改直接关闭；未保存修改先确认 | 保存中防止重复操作 |
| 移除 | 二次确认后删除本机副本 | 不删除电脑上的原文件 |
| 存储不可用 / 损坏 | 显示错误与重试入口，保留旧数据 | 示例仍可浏览、下载、关闭详情 |

### 文件边界

- 允许 PPT/PPTX、DOC/DOCX、PDF、TXT/MD、PNG/JPG/JPEG/WebP；拒绝可执行、HTML、SVG 等不在允许列表的格式。
- 单份上限 50 MB，一批最多 5 份、总计 100 MB；每账户本机草稿上限 200 MB。
- 空文件拒绝；内容 SHA-256 相同的不同文件名也拒绝重复保存。
- 名称 1–100 字符、简介最多 500 字符，学科和年级必填。
- 多文件共用学科、年级、简介、分享意向；可逐个改标题与资源类型。跨学科年级的资料建议分批整理。
- 本轮格式检查属于用户体验检查，**不等同服务端病毒扫描或文件安全认证**。

### 本机隐私与可靠性

必须主动勾选本机保存授权，同时确认已移除学生姓名、照片等个人信息。默认分享意向为“仅自己”。即使选择“校内”或“教研组”，本轮也不会分享，详情明确标为“未生效”。

存储键使用已验证会话的稳定 `user.id`，组件重新挂载仍绑定 `user.id:sessionVersion`，避免重新登录或修改密码后看不见自己的草稿。首次读取时自动合并同账户旧版 `id:会话版本号` 数据与收藏，保留同 ID 最新内容，写入新键和清理旧键位于同一事务；发现损坏内容则回滚，不覆盖、不静默丢弃。数据库协议升级到 v2，旧 v1 页面不能继续写回遗留命名空间；遇到旧页占用时提示关闭重试。

命名空间不是数据加密，也不是同一浏览器设备上的安全隔离；同源脚本、浏览器开发工具和有设备访问权限的人仍有可能读到存储。**请勿在公共机房保存敏感教学资料；下载并移除后再离开。** 清理浏览器、磁盘容量不足或浏览器回收存储均可能导致本机草稿丢失，因此本机草稿不能视作学校归档备份。将来引入多校身份时，由服务器按学校及账户共同隔离资源，不将这里的账户键直接当作租户权限。

读改写放在同一 IndexedDB 事务中，避免并行标签页互相覆盖整份集合；每份草稿带递增 revision，编辑时带原版本校验令牌。另一窗口已更新或已删除时，明确拒绝旧版本保存并保留当前输入，不能覆盖新内容或“复活”已删除的文件。窗口重新获得焦点时刷新数据。文件保存失败时不回退成“内存保存成功”。

## 5. 接通后端前必须补齐的业务约束

以下为设计方案，尚未实施。

1. **同学校身份来源**：由管理员维护学校及有效成员关系，不能把邮箱后缀、客户端学校选择框或 `scope=all` 当作学校边界。目前会话没有学校 ID，现有知识库全局 scope 不能直接充当同校共享权限。
2. **谁可以做什么**：同校教师和教研员浏览已发布资源；作者维护自己的草稿；组内资料另校验有效组成员；校级审核员审核指定版本，不能通过自填状态完成审核。跨校教研员按有效学校成员身份切换，不获得全局访问权。
3. **真实权属**：来源声明只是作者填写，不等于已完成版权核验。支持来源链接、授权附件、使用范围、举报和下架。
4. **两类发布分开**：分享给教师同事与发布给学生班级需要不同授权、脱敏要求和操作确认。
5. **文件与成果解耦**：下载次数不代表教学质量；收藏不代表审核通过；AI 提取与生成不代表教师审核通过。
6. **可追溯复用**：集体备课 / 课件工坊引用 `resourceId + versionId + fileHash`；修改派生版本保留来源、用途和操作者，不覆盖原版本。
7. **不给学生贴标签**：资源库默认采集教师资源操作记录，不借资源上传收集学生学习画像；学生文件另有合法业务依据、最小化字段和访问策略。

## 6. 建议数据模型与接口

沿用现有 Next.js / TypeScript 应用，新增清晰的服务端资源域，避免为单个模块同时引入多套 Web 框架。生产共享元数据建议 PostgreSQL；文件放私有对象存储或应用目录外的受控文件卷。

| 实体 | 关键字段与约束 |
|---|---|
| School / SchoolMembership | schoolId、userId、role、有效期、状态；成员由服务端验证 |
| Resource | schoolId、ownerId、当前草稿、标题、学科、年级、可见范围；范围包含必要 groupId |
| ResourceVersion | 不可变 versionId、resourceId、hash、bytes、真实 MIME、objectKey、来源与变更说明 |
| ReviewDecision | reviewerId、versionId、结论、理由、时间；结论绑定文件版本及 hash |
| Publication | versionId、发布者、受众、发布 / 撤回时间、权限策略版本 |
| ProcessingJob | scan / convert / extract、版本、状态、错误码、重试次数、幂等键 |
| ResourceGrant / Favorite | 授权对象或个人收藏；必须绑定学校和有效成员身份 |
| ResourceUse / AuditEvent | 引用工作区、目标成果版本、actor、requestId、时间、动作；追加记录 |

所有列表、详情、计数、搜索、预览、下载、收藏、审核接口都执行同一学校权限约束，不能只在上传入口过滤。采用数据库行级策略时，服务账号不得是超级用户、表所有者或 BYPASSRLS 角色；策略缺失要拒绝访问。连接池中的学校上下文必须限定在当前事务，避免跨请求残留。[PostgreSQL RLS 文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

拟定接口，不代表已存在：

| 方法与地址 | 用途及关键返回 |
|---|---|
| GET `/api/school-resources` | 服务端过滤 + 游标分页，数据及可见计数 |
| POST `/api/school-resources/uploads` | 验证有效身份、容量，建立私有隔离上传会话 |
| PUT `/api/school-resources/uploads/:id/content` | 流式写入，校验大小，不信任客户端 MIME |
| POST `/api/school-resources/uploads/:id/complete` | 核对 hash，入扫描队列，返回 jobId 而非“发布成功” |
| GET `/api/school-resources/jobs/:id` | 返回真实扫描 / 转换阶段、失败原因和重试策略 |
| PATCH `/api/school-resources/:id` | 乐观锁 If-Match，版本冲突返回 409 |
| POST `/api/school-resources/:id/submit` | 提交特定不可变版本审核 |
| POST `/api/school-resources/:id/reviews` | 独立审核者审批指定版本 |
| POST `/api/school-resources/:id/publish` | 发布已通过指定校验的版本，写审计 |
| GET `/api/school-resources/:id/versions/:vid/download` | 校验成员、版本和权限，输出短时私有下载 |
| POST `/api/school-resources/:id/withdraw` | 下架并阻断新授权；保留审计与引用提示 |

统一错误结构建议 `{ code, message, requestId, fieldErrors?, retryable? }`，所有写请求使用幂等键。任务超时、扫描不可用、权限撤销、连接中断、容量不足分别展示真实状态，不直接把异常转换成空列表。

## 7. 安全处理流水线

```text
有效学校成员 → 私有隔离上传 → 服务端格式 / 大小 / 签名校验
    → 本地恶意文件扫描 → 隔离转换 / 文本提取 → 作者核对 → 独立审核
    → 发布指定版本 → 受控预览 / 下载 → 引用记录 → 撤回 / 归档
```

上传允许列表、文件真实类型检查、随机对象键、大小限制、CSRF 防护、隔离存储、扫描和转换失败时阻断发布应组合实施。不要把带学生信息的文件交给公共在线扫描网站。Office 压缩包要限制解压后的总量、深度和文件数；防范压缩炸弹与外部资源引用。[OWASP 文件上传指导](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

建议无网络、非 root、只读根文件系统的转换 Worker，配置 CPU / 内存 / 超时，输入输出使用独立临时卷；LibreOffice 负责受限格式转换，PDF.js 使用自托管前端资源展示转换结果。预览失败仍不等于文件损坏或审核通过，原文件下载也必须满足安全与权限策略。[PDF.js 部署说明](https://mozilla.github.io/pdf.js/getting_started/)

LibreOffice 的 headless 模式和批量转换参数可用于 Worker，但每个任务必须分配独立、可写的用户配置目录，不能让并发任务共享配置锁；将该目录放在临时任务卷上，根文件系统仍保持只读。用固定 argv 调用已安装程序，不把上传文件名拼接成 shell 命令，不暴露 UNO 控制端口。转换完成后校验实际输出文件，再更新任务状态。[LibreOffice 官方启动参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

下载可选应用鉴权网关或很短有效期的对象存储签名 URL。签名 URL 是持有者凭据，不能当永久分享链接；撤回时停止签发。要求即时撤销时使用逐次鉴权网关，不能宣称已发出的签名链接会立刻失效。[S3 预签名 URL 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

## 8. 本地学校服务器与互联网部署

两种部署使用同一前端和资源 API 契约，通过存储适配器、身份配置和运行环境切换，不维护两套产品功能分支。

| 方面 | 学校内网 / 本地服务器 | 互联网 |
|---|---|---|
| 入口 | 校内域名 + 反向代理 + HTTPS | 公网域名 + TLS + 入口限流 |
| 应用 | Linux 服务器 Docker Compose：Next.js Node 服务 | 同镜像容器 / 受管容器平台 |
| 元数据 | PostgreSQL 持久卷，独立低权限账号 | 受管 PostgreSQL，私网连接 |
| 原文件 | 独立磁盘卷或受评估的 S3 兼容私有存储 | 私有对象存储；不公开 bucket |
| 处理任务 | 单独 Worker，轻量持久队列，可用 PostgreSQL job 表起步 | 扩展 Worker 数量；按负载再引入专用队列 |
| 认证 | 现有校内账号 + 有效学校成员映射；按学校实际情况对接统一认证 | 相同成员体系，多租户隔离，必要时统一认证 |
| 离线 | 资源整理和共享不依赖云 AI；镜像、字体、图标、预览包预下载 | AI 作为独立可选能力，不作为上传成功前提 |
| 更新 | 固定镜像摘要，离线升级包，迁移先备份后执行 | 分阶段发布，回滚应用并保留兼容 schema |
| 备份 | 数据库、文件卷、配置一致性备份；异机加密副本 | 数据库恢复点 + 对象版本 / 备份；定期恢复演练 |
| 运维 | 磁盘水位、扫描库更新、队列积压、失败任务告警 | 再增加租户配额、带宽预算、速率限制和滥用监测 |

配置建议集中在服务端：`DEPLOYMENT_MODE`、`DATABASE_URL`、`RESOURCE_STORAGE_DRIVER`、私有存储路径 / endpoint、单文件和学校容量上限、审核策略、内部认证参数。敏感值不使用 `NEXT_PUBLIC_` 前缀，不写入源码或文档，不在浏览器请求中暴露存储密钥。

**内网不是天然安全。** LAN 使用普通 HTTP 时浏览器的安全上下文能力可能不可用，本机草稿的 SHA-256 等接口尤其需要验证。正式学校部署统一使用浏览器信任的 HTTPS；`localhost` 开发例外不能外推到任意校园 IP。共享机设置自动登出和本地数据清理策略；断网界面不得把未同步内容显示为全校已共享。

生产部署不要把文件写进容器可丢弃层、`public/` 或无持久化保证的无服务器临时目录。CDN 不缓存私有资源正文，下载响应检查 Content-Disposition / nosniff / cache policy。

## 9. 分阶段接通与验收
