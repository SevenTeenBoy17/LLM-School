### R1-FE-001 P1 上传弹窗解析 interval 未在关闭/重置时清理

- 位置：`components/knowledge/UploadDialog.tsx:32`
- 证据：`startParse` 内部创建 `setInterval`，只在进度到 100 时 `clearInterval(t)`；`reset` / `close` / `onOpenChange(false)` 没有清理该 interval。
- 影响：用户开始解析后立刻关闭弹窗，interval 仍可能继续 setState，导致隐藏状态变化、内存泄漏或重新打开时进度错乱。
- 建议：用 `useRef` 保存 interval id；在 `reset`、`close`、`onOpenChange(false)` 和组件 unmount 中统一清理。

### R1-FE-002 P2 上传弹窗图标按钮缺少可访问名称

- 位置：`components/knowledge/UploadDialog.tsx:55`、`components/knowledge/UploadDialog.tsx:118`
- 证据：关闭按钮和移除文件按钮都只渲染 `<X />`，没有 `aria-label` / `title` / 可见文本。
- 影响：读屏用户无法知道按钮含义。
- 建议：分别添加 `aria-label="关闭上传弹窗"`、`aria-label={\`移除文件 ${f.name}\`}`。

### R1-FE-003 P1 聊天附件入口可见但未接真实上传链路

- 位置：`components/chat/Composer.tsx:90`，`app/(shell)/chat/page.tsx:81`
- 证据：上传文件 / 图片 / 语音按钮可见，但 `ChatPage` 只提交 `message/modelId/history` JSON，不包含文件内容或文件元数据。
- 影响：用户会以为附件已支持，实际无法进入后端处理，属于产品可信度问题。
- 建议：接入真实文件 input/drop + multipart 或禁用这些按钮并标注“即将开放”。

### R1-FE-004 P1 登录轮播指示按钮处在 `aria-hidden` 容器内

- 位置：`components/login/CardCarousel.tsx:304`
- 证据：浏览器 DOM 检测在 `/login` 发现 `aria-hidden="true"` 容器下有 4 个可聚焦 button。
- 影响：读屏树隐藏但键盘仍可聚焦，形成焦点/语义不一致。
- 建议：移除容器 `aria-hidden`，保留按钮 `aria-label`；或把圆点改为非交互元素。

### R1-FE-005 P2 Switch 与 Field 标签关联不完整

- 位置：`components/ui/switch.tsx:11`、`app/(shell)/agent/new/page.tsx:396`
- 证据：多个 `Switch` 调用方未传 `aria-label` / `aria-labelledby`；`Field` 仅视觉渲染 `<Label>`，未通过 `htmlFor/id` 关联 Input/SelectTrigger。
- 影响：表单控件可访问名称不稳定。
- 建议：封装 `SwitchRow` 时传 `aria-label={label}`；`Field` 生成稳定 id 或允许子控件传 `aria-labelledby`。

### R1-FE-006 P2 Topbar 搜索区看起来可点击但不是可聚焦控件

- 位置：`components/shell/Topbar.tsx:61`
- 证据：浏览器 DOM 检测在所有登录后桌面页面发现同一个 `cursor-pointer` 搜索块；它是 `div`，没有 `role`、`tabIndex`、键盘事件。
- 影响：键盘用户无法触发搜索；视觉反馈暗示的交互不可达。
- 建议：改为 `button` / `combobox`，补 `aria-label` 和 `Ctrl/⌘ K` 快捷键处理。

### R1-FE-007 P2 宽泛 suppressHydrationWarning 掩盖潜在时间差异

- 位置：`app/layout.tsx:26`、`app/(shell)/dashboard/page.tsx:42`、`app/(shell)/learn/page.tsx:61`
- 证据：`html` / `body` 使用 `suppressHydrationWarning`；dashboard/learn 使用 `new Date().getHours()` 生成问候。
- 影响：真实 hydration mismatch 可能被顶层 suppress 掩盖。
- 建议：问候语改为 mount 后客户端计算或服务端注入同一 hour；缩小 suppress 范围。

### R2-BE-001 P1 `/api/audit` 允许匿名写入审计日志

- 位置：`app/api/audit/route.ts:7`
- 运行时证据：匿名 `POST /api/audit` 返回 200；admin 随后 `GET /api/audit` 可看到 `userId="anonymous"`、`role="none"` 的测试 action。
- 影响：外部请求可污染审计日志，制造噪声或掩盖真实越权事件。
- 建议：仅接受 proxy 内部签名 beacon 或已鉴权请求；限制 `path/action` 枚举并加限流/去重。

### R2-BE-002 P1 `/api/class` 与页面权限矩阵不一致，admin 可直接读实名学情

- 位置：`app/api/class/route.ts:16`，`lib/nav.ts:31`
- 运行时证据：页面权限 `canAccessClass` 只允许 teacher/researcher；但 admin 直接 `GET /api/class` 返回 200，`masked=false`，含 `name/mastery/weakest`。
- 影响：admin 虽不应进入 `/class` 页面，却可直接读取班级实名诊断数据，违反最小权限。
- 建议：API 复用 `canAccessClass(user.role)`；或显式定义 admin 是否可读，若可读也应做相应审计和最小化。

### R2-BE-003 P1 空库自动 seed 演示用户缺少生产显式开关

- 位置：`lib/server/db.ts:61`
- 代码证据：`db()` 总是调用 `seedIfEmpty`；`seedIfEmpty` 在空 users 表时插入 teacher/student/admin/research 演示账号。
- 影响：如果生产/预发环境挂载空 SQLite，会自动生成演示账号，存在账号暴露风险。
- 建议：用显式 `EDUAI_ENABLE_DEMO_SEED=true` 或测试环境 flag 控制；生产默认禁止 seed。

### R2-BE-004 P2 安全分类硬门仍依赖关键词启发式

- 位置：`lib/safety/classifyIntent.ts:2`、`app/api/chat/route.ts:37`
- 证据：当前运行时对已列关键词有效，但代码注释也说明启发式可被变体绕过。
- 影响：危机/学术诚信的同义表达、错别字、隐喻、拼音变体可能漏判。
- 建议：加入服务端语义安全分类和人工复核队列；关键词作为 fast prefilter。

### R2-BE-005 P2 `/api/safety` 与 crisis 工单缺少限流/去重

- 位置：`app/api/safety/route.ts:18`、`app/api/chat/route.ts:43`
- 证据：每次有效 help/report 或 crisis 命中都会 `addTicket`，未看到 per-user throttle/dedupe。
- 影响：可被登录用户刷工单，影响安全/心理团队处理效率。
- 建议：按用户、类型、时间窗做去重；紧急项仍要保留升级路径。

### R2-BE-006 P2 会话 token 验证未做 schema/DB 复核

- 位置：`lib/server/authToken.ts:73`
- 证据：`verifySession` 验签后直接 `return payload.u as SessionUser`；非生产环境缺少 `EDUAI_SESSION_SECRET` 时使用内置 dev secret。
- 影响：签名密钥一旦泄露，角色/班级等 claims 无 DB 复核或撤销版本约束。
- 建议：验证 payload schema；关键 API 可按 user id 回查 DB；共享/预发环境也强制配置密钥。
