基线：[v6 方案](./EduAI-Prism-个人庄园-QQ农场对标问题清单与教育化升级方案-v6.0-20260920.md)；[v6 实施与验收记录](./EduAI-Prism-个人庄园-v6重构实施与验收记录-20260920.md)。

## 1. 核心判断

**保留目前的手绘农场，不推倒重做；先修学习与数据断点，再把仓库、建筑、装扮变成同一套可理解的交互。** QQ 农场值得借鉴的是空间秩序、工具语义、物品状态、收获反馈和连续操作，不是把商业农场的催促、消耗、排名照搬进学校。

当前版本已不是静态原型，但仍存在“能打开”不等于“能完成长期使用”的缺口：

1. 初中学生面对所有学段示例，正式任务分派尚未建立。
2. 旧题奖励与新示例奖励不一致，而且评价状态受奖励金额影响。
3. 创作的“继续编辑”与“重新创作”没有明确区分，新一轮表达又可能被旧的已接受状态锁住。
4. 积分、装饰收藏、场景摆放尚未闭环；地块成长只展示局部学习来源。
5. 跨学科已有共同问题，但还没有必须汇合的共同成果与版本约束。

优先顺序：**冻结共享契约 → 基本使用修复 → 教师最小发布/分派及评价奖励 → 来源链与跨模块 → 仓库装扮 → 稳态验证与课堂试点**。assignment/taskRun、作品版本与评价奖励契约须先明确；样式、空状态和美术样板可并行，不宜先大批量生产资产。具体工作包以第 10 节为准。

| 日常玩法托盘 | 图鉴、装饰、升级等低频入口集中展开，主场景不常驻一整排菜单 | 用“更多”收纳低频功能；不能堆图标冒充功能丰富 |
| 成就图鉴/普通作物 | 系列进度、分类徽章、分页；普通作物有二级分类、星级/条件和获取入口 | 成果按教学项目组织，引用作品与数据；不用巨大收集分母或好友比拼评价学生 |
| 好友抽屉 | 右侧窄栏、搜索/刷新/筛选/分页；当前只见一行与本人资料相符的记录 | 班级只读参观入口简洁；本轮没有可据此证明的跨好友访问链 |
| 活动托盘/欢乐季 | 托盘大量图标；活动主页与规则页在同一外壳切换，正文浅纸面；关闭回到农场 | 每次突出一个教学项目，保留“当前内容/规则”层次；不照搬周期收益、随机倍奖或现金购买机会 |

日常托盘的一次定位尝试最终打开的是图鉴，因此装饰编辑器仍未确认，不把尝试当作成功。可访问树没有暴露游戏内部仓库/目录控件，本轮依据截图定位；EduAI 应继续保留 DOM 语义、焦点与键盘等价入口，而不是复制这一限制。

### 5.2 风格与机制转译

| 参考特征 | 保留的视觉/交互原则 | 教育化调整 |
|---|---|---|
| 斜俯视农田、连续草坪、房舍围合 | 清晰主场景、统一透视、地面锚点、前后遮挡 | 作物反映已发生的照料与作品轨迹，不代表学科能力等级 |
| 木牌、浅色描边、压下反馈 | 共用木质壳和小面积材质；按钮有 hover/pressed/focus | 文字与图标用可访问 DOM，不烘焙进图片；不把整个学习正文做成木纹 |
| 角落账号资源、边侧功能、底部农具 | 场景中央留给土地；操作组位置稳定 | 上方任务/复习/工坊，左侧仓库/成果，底部农具；健康退出固定可达 |
| 仓库、商店、摆放、收获相互关联 | 物品状态明确，可预览、撤销、回收 | 商店改“装扮集市”，只花已确认的平台积分，不收费、不抽取稀有奖励 |
| 成熟/锁定/选中各有标记 | 同一对象多状态可辨 | 锁定解释实际政策；答错不枯萎；不以红点和倒计时制造压力 |
| 好友访问与合作建设 | 可见共同空间和有意义贡献 | 同班自愿公开、只读参观、教师审核公开作品；不互偷、不公布能力排行 |

**美术策略**：复用 v6 的光照、草地、线条和比例作为唯一母版；QQ 作为参考标杆，不在同一场景拼接两套素材。未经授权不直接发布参考产品的标识、角色或提取资产。保留原创图样的来源、版本、审批记录。

## 6. 页面与按钮的完整闭环

### 6.1 一个空间，六类工作

```text
今日学习 [当前任务/继续上次] → 证据 → 反馈 → 修订/反思 → 成果
温室 [到期复习]            → 变式练习 → 反馈 → 更新复习计划
工坊 [我的草稿/新作]       → 引用证据 → 保存 → 提交 → 审核 → 入册
仓库 [收获/种子/装饰]      → 查来源或预览布置 → 保存布局
班级花园 [单元共建]        → 个人贡献 → 教师确认 → 班级里程碑
健康节奏 [结束今日学习]    → 保存状态 → 只读浏览/返回学习中心
```

主场景不显示全部流程步骤。状态卡只给当前最重要的一件事；工坊、仓库、温室各自承载细节，避免将农场变成仪表盘。

### 6.2 图形化入口与状态契约

| 入口 | 主命令 | 返回结果和后续 | 不可用时应怎样呈现 |
|---|---|---|---|
| 空地/种子 | 预览品种、播种 | 地块 ID、cropId、revision、操作回执；关闭后焦点回原地块 | 未开放注明政策；无权限不给假按钮；不能只 toast 成功 |
| 水壶 | 照料 | 明示 8 点或当前政策价格、可用授权；确认后更新余额、阶段、来源 | 不足时列来源与可参与任务；示例不发奖须明确，不诱导无效答题 |
| 仓箱 | 收获 | 收获记录、库存、种植周期来源，动画在服务器确认后播放 | 未成熟展示阶段，不执行空操作；未知响应先查回执 |
| 装饰/移动 | 预览、旋转（素材支持时）、确认、撤销、收起 | 当前库存实例、坐标、占位、layoutRevision；保存成功才离开 | 冲突位置红框加文字；缩放不改变世界坐标；失败保留预览 |
| 手册/笔 | 查看来源、保存草稿、提交老师 | draft/待审/退回/接受/入册有不同标记和可执行下一步 | 必填未满足说明缺项；老师未分配允许保存，不能假装提交成功 |
| 同班伙伴 | 参观、返回我的农场 | 公开装饰和授权成果，返回恢复自己的位置 | 未公开与无人加入区分；不得返回其他学生私密证据 |
| 健康节奏 | 暂停、结束、返回学习中心 | 已保存摘要、下次建议；不扣分、不损失作物 | 有未确认操作先恢复回执，再决定退出 |

按钮统一具备常态、悬停、键盘焦点、按下、忙碌、成功、失败、结果未知八类状态；不是每个按钮都要八张图片。图形按钮提供名称/提示，危险清理必须确认，错误保留用户输入。

仓库优先显示已拥有物品及数量；同品种装饰一行，展开到库存实例。筛选用标签/分段控件，排序用菜单，数字数量用步进器。收获可查来源，不新增出售换分形成刷分循环。

桌面保持全景与适度密度；平板允许平移农田但操作面板不一起缩小；手机保留清单并提供主动切换场景。弹窗正文独立滚动，关闭和主操作在小屏仍可见，软键盘不覆盖编辑区域。

## 7. 跨学科必须共同解决一个问题

### 7.1 示例项目：校园花圃怎样节水而不影响植物状态

这只是待教师审核的教学设计，不是已验证课程。模拟数据与真实采集必须分开标记，不能把游戏内动画当作植物实验数据。

| 学科贡献 | 可核查产物 | 对共同成果的必要作用 |
|---|---|---|
| 数学 | 100 L 与 75 L 的差值、以 100 L 为基准的 25% 节水率，单位和计算过程 | 给出量化比较，错误基准不能通过相应量规 |
| 科学 | 控制面积/种类/天气等变量；9/10 状态说明；指出仅一次观察不能证明长期效果；设计重复实验 | 限定数学结果能说明什么，提出进一步证据需求 |
| 语文 | 给学校的建议：主张、引用数据、解释、限制、后续验证 | 将计算与科学限制整合成可讨论方案，不能只是另做一题 |
| 综合成果 | 同一 datasetVersion 上的节水建议单，含以上必要引用和教师评价 | 任一贡献缺失标“尚待补充”，而不是三个独立对勾冒充项目完成 |

低学段可改为图片观察、多少比较和口述；高段加入单位/比例基础与记录表；初中加入对照、重复与论证边界。具体年级和学科知识仍由教师审核，不能只换题目标签。

### 7.2 真实证据链与奖励链分开

```text
学校/班级 → 教师发布版本 → assignment → taskRun/projectRun
                                 ↓
资源/数据版本 → 尝试记录 → 规则反馈/教师量规 → 修订 → 学习成果版本
                                                   ↓
                                           复习与成长档案
                                                   ↓ 可选的激励决策
               policyVersion → grant → 消费明细 → 照料动作 → 种植周期 → 收获
```

证据记录至少含任务/资源版本、学生归属、尝试序号、来源类型、提示与辅助、评价者、量规版本和时间。查看/点击/停留只是过程上下文；任务提交也不自动代表掌握。AI 可协助反馈，但不能把未经教师/规则核准的评语作为高确定性能力结论。

奖赏不决定评价：答对、订正、表达质量和迁移表现分维记录；是否授予成长能量由另一条政策决定。更正教师判断要追加撤销/调整记录，不篡改旧证据；已经消费的奖励如何调整须有专门规则，禁止直接产生负余额或倒扣历史学习成果。

积分用于非必需装饰；成长授权用于可选照料；作品、草稿、反思、复习始终免费。新生和需要更多帮助的学生不应因能量少而无法进入学习内容。无每日签到连胜、离线枯萎、随机宝箱、稀缺限时抢夺或公开成绩排名。

间隔复习、主动提取、图文结合可作为设计依据，但不保证本产品的学习效果；需通过课堂验证。依据：[IES 学习与教学组织实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。

## 8. 技术路线：增量接通，保留现有安全边界

以下实体与 API 是**拟新增/调整契约**，不是已存在接口清单。

| 领域 | 拟调整对象 | 服务端不变量 |
|---|---|---|
| 任务分派 | Assignment、assignmentVersion、gradeBand、resourceVersion | 教师当前学校/班级权限；已发布版本不原地覆盖；未知学段不猜测 |
| 项目协作 | ProjectRun、Contribution、ArtifactSource | 必需贡献齐全且来源版本一致才能完成；保留个人贡献，不能由组长一次提交冒充全组学会 |
| 表达/草稿 | taskRunId、artifactId、revision、acceptedRevision | 草稿更新与另存区分；并发校验；已审核版本不可变；新 run 不继承旧提交锁 |
| 奖励 | EvaluationDecision、RewardPolicy、Grant、Ledger | 评价与奖励分账；任务里程碑唯一键；来源可追溯；重复请求无重复到账 |
| 场景 | PlantingCycle、PlotAction、GrantConsumption | 每次照料全额守恒；显示全部来源；收获/清理不删除学习账 |
| 装扮 | CatalogVersion、InventoryInstance、LayoutRevision | 价格服务器计算；扣分与入库同事务；放置合法性、唯一实例和占位服务器校验 |
| 参观 | ClassMembership、ManorPublication | 当前班级与发布范围验证；只读字段白名单；撤回后拒绝新读取、使受控缓存失效 |

建议端点：`GET /api/v2/manor/assignments`、`POST /api/v2/manor/task-runs/:id/submissions`、`PATCH /api/v2/manor/artifacts/:id`、`GET /api/v2/manor/plots/:id/history`、`POST /api/v2/manor/decorations/purchases`、`PATCH /api/v2/manor/layout`、`POST /api/v2/manor/publication`。路径最终由接口设计评审决定；不占用旧接口悄悄改变语义。

写命令携带 operationId/expectedRevision，结果包含明确业务状态、服务器版本、correlationId 和必要增量。失败区分权限、缺项、冲突、余额不足、服务不可用与结果未知。客户端不得将超时等同于未提交，不自行换 ID 重试扣款。

先盘点旧收藏坐标与新世界坐标，制作可逆映射；无法映射的物品进入待布置库存而不是丢弃。迁移对照旧余额、库存、历史行数和来源关系，先隔离副本验证；不重置真实学生庄园。

### 8.1 两种部署

- **学校内网首期**：延续当前单实例服务与持久化数据库；美术、字体、教学内容本地可用；HTTPS/统一学校时间/备份恢复由运维配置。SQLite 使用一致性备份，不能在线只复制主库忽略 WAL。图片生成属于开发资产流程，不成为课堂必需外网请求。
- **公网试点**：同源应用与 API、最小权限文件访问、限流、会话安全、脱敏日志和灾备；资源访问按学校/班级复核，不能只靠前端隐藏。上线前独立做外网与隐私审查。
- **多校/高并发后续**：先明确 tenant 边界与负载，再评估集中数据库、对象存储与后台任务；不把本地 SQLite 测试通过当作多实例可写和多租户已实现的证明。
- **HTML 活动资源**：接入既有隔离运行器与资源版本，使用最小沙箱权限和校验后的消息协议；活动页面不得直接写积分/成绩。外部结果需服务器验证来源与归属，不能仅凭 iframe 发来“完成”就奖励。
- **弱网**：静态素材可缓存；私密作答缓存按账户隔离并有清除策略。跨端奖励以服务器为准，不在本地离线伪造已同步成绩。
- **数据生命周期**：学校确认原始作答、过程事件、公开作品各自的保存期限、退出处置与备份保留规则，不无限期保留所有点击。公开展示使用经审核的最小字段投影，不携带私密证据访问链接；撤回后拒绝新读取并使受控缓存失效，备份恢复重新应用删除/撤回标记。不承诺收回已下载或截图保存的副本。

## 9. 资产生产清单与视觉验收

先制作一栋温室、一个仓库弹窗、一套工具状态作为风格样板；通过后再批量生成。优先沿用当前原创资产，不因“高清”统一加载超大原稿。

| 资产组 | 首批建议数量与规格 | 关键要求 |
|---|---|---|
| 建筑 | 温室、工坊、仓库、班级花园入口，共 4 组；1024px 透明原稿，按实际尺寸导出 WebP | 相同斜俯视、线宽、光照；不烘焙文字与用户状态；拆分可交互层 |
| 面板材质 | 1 套木框九宫格、1 套纸面、1 套页签底纹 | 正文保持平静浅底；边框可伸缩；不把一张图片拉伸成整个弹窗 |
| 农具/入口图标 | 现有农具复用；补装饰移动、收起、来源、复习、草稿等约 8 个专用图样 | 普通保存/关闭/返回使用既有图标库；自定义图样统一物体比例，不把文字画进图里 |
| 装饰 | 先 6 类：路牌、花圃、座椅、雨量筒、观察台、节水桶；512–1024px 原稿 | 部分对象可关联真实观察工具；无道具必须付费；实例锚点与占地明确 |
| 作物与土地 | 复用 v6 六类四阶段和两类地块，补状态标记而非全部重画 | 状态与后端一致；不增加虚假的虫害、枯萎、成熟倒计时 |
| 学习证据附件图样 | 数据表、观察记录、证据夹 3 组 | 正文/数值真实 DOM 或生成表格，不让生成图片承载可变答案 |
| 反馈动效 | 照料、收获、入册、保存成功 4 组 | 以实际操作回执触发；短促不连播；减弱动态模式改静态反馈 |
| 空状态 | 无收获、未分派、无待复习 3 幅小插画 | 低视觉权重，配直接下一步；禁止人物夸张奖励表情遮挡任务 |

统一浅自然光、清亮草绿、木褐结构与少量蓝/黄/白点缀；色彩从当前母版取样确认，不以本轮目测 HEX 当作 QQ 官方色板。学习面板用深色文字，强调状态可加符号，不仅靠颜色。

生产配置模板（JSON 是制作规范，不是声称恢复了原产品提示词）：

```json
{
  "assetId": "manor-greenhouse-v7",
  "reference": "approved-original-manor-v6-style-board",
  "purpose": "interactive review building",
  "style": "hand-painted isometric farm, crisp outlined shapes, soft daylight",
  "canvas": { "width": 1024, "height": 1024, "background": "transparent" },
  "composition": "single complete building, no crop, bottom-center ground contact",
  "exclude": ["text", "logos", "watermarks", "baked UI", "account data"],
  "states": ["normal", "review-due", "selected"],
  "delivery": ["source PNG", "runtime WebP", "anchor metadata", "provenance"]
}
```

如供应工具不支持透明背景，可另生成可抠图底色；绿色植物不宜机械使用纯绿底，以免抠掉叶片。优先原生透明，或按主体颜色选择对比底色并检查边缘；不得把绿边带进场景。运行资源应有 alpha、尺寸、pivot、占位、许可/来源、生成批次、版本与哈希。

本轮未调用生图，未新增图片或付费服务。未来使用实际可调用模型并记录返回元信息；不能因用户指定名称就声称使用了未暴露的 image-2.5。比对目标是统一风格和可用性，不是复制品牌标识或从截图“还原原始提示词”。

普通文本对比度目标采用 WCAG 2.2 AA 的 4.5:1，大号文字 3:1；具体字体尺寸应按标准定义计算。依据：[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。44px 是本项目较宽松易触达的设计目标，不冒称 WCAG 2.2 AA 一律要求 44px。

产品指标建议：任务恢复成功率、来源能否找回、草稿重复率、教师审阅耗时、错误恢复成功率、适龄任务完成质量、学生自主结束比例。留存只作为辅助；不把停留越久、点击越多当作学习越好，不预先承诺任何增长百分比。

课堂试点需教师确认课程、学生使用条件与数据范围，先小规模可退出测试；收集真实操作困难、教师工作量和作品质量，不能从自动测试推断教育有效。具体休息节奏由学校和教师设置，本方案不提供医学或法规合规结论。
