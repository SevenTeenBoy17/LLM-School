## 4. 视觉与界面设计决策

### 4.1 保留当前用户认可的视觉基础

保留全幅手绘场景、斜向地块、绿色自然环境、暖木边框、纸质工作面、大图形工具、边缘建筑。不要改成数据后台、卡片墙或大面积紫色渐变。视觉升级是提高层级、图形语义和资产一致性，不是把农场去掉。

**同一套视觉语法，三种阅读密度：**

| 场景 | 呈现方式 | 优先保护 |
| --- | --- | --- |
| 农场浏览与布置 | 画面为主、短标签、小型状态牌 | 土地可见、工具好点、对象明确 |
| 做任务与写作品 | 稳定纸质工作面、清晰步骤、正文和附件 | 阅读、输入、草稿和教师目标 |
| 查证据与教师审核 | 简约列表、来源、版本、评分依据 | 信息准确、快速比对、不用装饰遮内容 |

### 4.2 桌面布局

```text
返回学习中心  个人庄园 / 当前项目             同步状态  信箱  帮助  设置

学习者与积分摘要            今日下一步（可收起）            项目 / 温室 / 工坊
```

删除无业务含义的“QQ农场 / 新增应用”外壳仿制入口。品牌显示个人庄园，不宣称 QQ 官方关联。保留原来的操作方位习惯，减少学习成本。顶部主导航与农场 HUD 不重复摆两套同等权重的入口。

建筑与顶部入口只是同一功能的两种入口，调用同一组件和状态，不各建一套实现。建筑热点有可见标签及键盘等价入口。

### 4.3 表面、排版、色彩与动画

- 轻操作用对象旁的浮层；任务/仓库/工坊用主工作面；同一时刻只保留一个主工作面，关闭后恢复原焦点和场景位置。
- 主标题建议 20–24px，正文 16px，密集辅助信息 14px；不以 11px 小字承载教学内容；字体不随视口宽度无限缩放。
- 草地与天空承载环境色，木/纸承载控件，深墨色承载正文；蓝用于同步/信息，绿色用于成功，琥珀用于待关注，红只用于错误/危险。颜色不作为唯一状态编码。
- 装饰框与按钮内容分离。纹理可用切片，文字、价格、进度、角标都由 DOM 渲染。正文背景保持低纹理，避免文字压在草地上。
- 项目建议目标：主要触控区域至少 44×44 CSS px，优先 48×48；这是本项目易用性目标，不冒称 WCAG 2.2 AA 的统一最低要求。WCAG 2.5.8 的最低目标及例外见 [W3C 原文](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
- 按压 100–160ms，开面板 180–240ms，成功对象变化 300–500ms；均为设计目标，待设备测试。先拿到权威结果再播放成长，不用动画伪造保存成功。
- 尊重减少动态效果设置；静音不影响信息传达；不持续闪烁角标、不循环催促领取。

### 4.4 统一坐标与移动端

24 个 plotId 保持稳定，世界坐标、底图尺寸、地块多边形、作物锚点和遮挡层级属于同一个版本的 SceneManifest。画布平移/缩放后只应用一次共同变换，不用独立百分比网格凑位置。

宽屏展示场景；窄屏保留简化 HUD 和“场景 / 列表”切换。列表提供与场景等价的查看、继续任务、照料、追溯、布置操作，不要求学生准确点击缩小后的微型土地。首期先做列表等价链路，再做可选平移缩放。

## 5. 真正的教学闭环

### 5.1 两条链分开，但能追溯

```text
教学链：真实问题 -> 目标 -> 学习/实验 -> 证据 -> 反馈 -> 修订
                    -> 教师接受/规则判定 -> 成果归档 -> 延时复习/迁移

庄园链：选择项目 -> 选择展示地块 -> 展示当前阶段 -> 看来源和下一步
                    -> 学习积分装扮 -> 班级展示与反馈
```

农场是教学链的投影，不是教师判定之前的捷径。浇水次数、在线时长、金币、点赞和收获数量都不能直接产生“学会了”的结论。

### 5.2 首个项目建议：校园花圃怎样节水

这是可实施的教学设计示例，不是现有已发布课程。首期建议由教师选择适合的高小或初中年级，并审核目标、数据与评价标准。

驱动问题：在不影响指定植物健康的前提下，怎样改进校园一小块花圃的浇灌方案？

| 阶段 | 学生行为 | 必须留下的证据 | 庄园呈现 | 教师/系统判断 |
| --- | --- | --- | --- | --- |
| 明确问题 | 选择观察区，写下假设和比较方法 | 假设、变量、测量单位、观察计划 | 为项目挂牌；可自由选择外观作物 | 目标与方案是否匹配，不因选择某作物加分 |
| 获取数据 | 实测或使用标明来源的等价数据；可运行教师 HTML 实验 | 时间、条件、原始记录、来源类型、附件版本 | 观察台出现“有待整理记录” | 记录完整性；模拟与真实数据不能混标 |
| 数学分析 | 比较用水量、比例、图表；说明异常值 | 计算过程、图表、单位、异常说明 | 证据册增加可打开的图表页 | 初中增加变量与误差讨论，低年级不强上同一量表 |
| 科学解释 | 用数据解释方案优劣，并提出反例/局限 | 结论与证据引用、局限和需再验证的问题 | 工坊形成论证草稿 | 不能把相关性写成必然因果 |
| 表达与行动 | 面向班级写建议或做演示；说明为何采纳某方案 | 报告/录音/展示稿，引用同一组数据 | 展示位出现作品草稿 | 语文承担表达与论证任务，不只写一句感想 |
| 修订与归档 | 依据反馈修正，再提交 | 前后版本、修改说明、评价记录 | 成长阶段更新，出现可追溯成果 | 教师接受后入册；未接受也保留努力与版本记录 |
| 迁移与复习 | 换花圃/土壤/季节条件作新判断 | 新问题答案、理由、反馈、后续计划 | 温室出现新的学习记录 | 不靠重复同一正确选项刷奖励 |

跨学科成立的条件：科学决定应测什么，数学帮助比较数据，语文组织有根据的建议，信息科技帮助记录或验证模型；各科使用同一个真实问题和证据集。缺少任何一环都能解释最终建议哪里站不住，而不是“做语文题得竹子，做数学题得麦子”。

不强制每个项目包含所有学科。没有实测条件时提供等价数据集或模拟任务，明确标为模拟；不要求家庭购买器材、拍摄私人住址或持续守候上线。

### 5.3 年龄与任务负担

| 年级带 | 学习支架 | 输入与评价 |
| --- | --- | --- |
| 小学低段 | 一屏一个行动、图片序列、教师示范、少量选择 | 口述/照片/简短记录，教师确认，不默认自由社交 |
| 小学高段 | 明确问题、基本数据表、对比与解释提示 | 简短证据说明和修订理由 |
| 初中 | 变量控制、图表、误差、反例、论证 | 独立过程、引用和多版本作品 |
| 年级未知 | 使用教师分配目标或请求完善信息 | 不根据浏览习惯、年龄猜测自动判定能力 |

“8 分钟”只能是预计用时，不是必须耗满或倒计时限时；作品任务可跨天完成。项目长期周期与一次登录的短时行动分开。

### 5.4 理论依据与适用边界

- 元认知支架：把“计划、监控、评价”嵌入具体学科任务；界面落到假设、过程检查、修订说明，而不是泛泛情绪打卡。[EEF 指南](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/metacognition)
- 自主性、胜任感、归属感：允许有限选择、提供可改进反馈、强调共同成果。本方案据此建议不用公开总榜或奖励压力作为主驱动；这些是产品推导，不是研究直接证明本产品有效。[Ryan 与 Deci，2020](https://selfdeterminationtheory.org/wp-content/uploads/2020/06/2020_RyanDeci_IntrinsicandExtrinsic.pdf)
- 提取练习：一项包含 88 名、平均约 10 岁儿童的词语学习研究支持提取练习的记忆收益；它不直接证明所有年龄、学科或庄园机制有效。温室应包含有支架的回忆和反馈，不只展示复习日期。[Karpicke 等，2016 原始研究](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2016.00350/full)

不把文献中的平均效果变成本产品提升成绩或留存的承诺。复习间隔由课程与试点结果校准，不能把固定 24/72 小时称为已验证个性化算法。

## 6. 学生端与教师端的串联

| 现有模块 | 庄园如何承接 | 返回该模块时保留什么 | 信任边界 |
| --- | --- | --- | --- |
| 学生首页 / 今日学习 | 提供“继续上次项目”和下一步 | projectId、taskRunId、完成进度 | 首页点击不是学习完成证据 |
| 项目活动 | 作为跨学科项目和教师分配的主要来源 | 任务、提交版本、教师反馈 | 不另造一套互相不认识的审批状态 |
| 学习资源 / HTML 活动 | 从项目任务打开指定资源版本，同窗操作或独立安全窗口 | activitySessionId、草稿/结果引用、原任务入口 | 打开 HTML、播放视频不等于学会；资源自报得分是未核验来源 |
| AI 对话 / 工具 | 学生主动选择一段帮助记录或作品作为过程材料 | 原会话的受控引用、学生自己的解释 | 不自动采集全部聊天，不把 AI 答案当独立掌握 |
| 小测 / 错题 | 接收已存在的真实练习与订正事件 | objectiveId、attemptId、作答版本和反馈 | 点击“看答案”不等于独立完成 |
| 成长总览 / 档案袋 / 徽章 | 展示庄园接受成果，点击回到证据时间线 | 稳定 evidenceId、artifactId、评价版本 | 私密草稿和公开展示分别授权 |
| 教师庄园证据 | 看待审队列、原始材料、版本差异、评价依据 | 学生/班级范围、任务、rubricVersion | AI 可辅助整理，不替教师假定已批准 |

教师端沿用已有“庄园证据”入口，增加“待审 / 需修订 / 已接受”筛选、预览、逐条反馈、版本对照和退回理由；不再新增另一个孤立教师工作台。允许批量打开队列，不默认一键批量判定全部掌握。

## 7. 积分、成长与荣誉：不要混成一种货币

### 7.1 当前平台已有的规则

`lib/gamify.ts` 的 `POINT_RULES` 与 `db.ts::syncPoints` 已提供以下积分来源：

| 来源 | 当前每次积分 | 当前每日计分次数上限 |
| --- | --- | --- |
| 完成小测作答 | 5 | 10 |
| 错题复习记录 | 10 | 5 |
| 项目经教师批准入册 | 30 | 1 |
| 教师正向评价 | 10 | 3 |
| 在线天数、AI 提问、生图、点赞、共建认捐 | 0 | 不产积分 |

这些是现有规则，不是本轮新调数值。小测积分代表参与行为，不能直接标为“掌握积分”。同一成果可能触发项目和教师评价两类事件，现有跨类别奖励是否符合学校策略，需要明确，不应把业务上的重复奖励与同事件的技术重放混为一谈。

### 7.2 推荐采用三层语义

| 层 | 学生看到什么 | 能做什么 | 禁止 |
| --- | --- | --- | --- |
| 学习积分 | 积分余额、最近来源、规则说明 | 兑换可选装饰；自愿班级共建 | 兑换答案、跳过审核、补买掌握、真钱充值 |
| 学习证据 / 成长授权 | 本项目已认可的阶段和来源 | 驱动真实学习里程碑的视觉成长 | 由积分、点赞或重复浇水反向签发证据 |
| 荣誉与档案 | 曾完成的成果、徽章、版本与教师反馈 | 长期保留与授权展示 | 装扮消费扣掉荣誉、把草稿出售或被好友偷取 |

HUD 默认只显示学习积分和当前项目进度。成长授权的数量与用途放到“查看来源”详情，减少学生理解两个余额的负担。装扮路径始终说明“仅影响庄园外观”。

**本版明确修订建议：保存草稿、反思、提交教师、执行复习不应再收费或消耗成长授权。** 当前保存工坊作品要求授权的规则应在实施前作版本化变更；授权消费保留在需要的可选庄园动作，并保持旧流水可追溯。不能仅改前端跳过服务端校验。

### 7.3 账本不变量与迁移

1. 同一来源事件用稳定 `sourceType + sourceId + principalId` 去重；奖励政策版本用于审计，不因升级而重奖旧证据。
2. 已存平台积分不清零、不强制换币；不把旧积分流水行数换算成新证据。
3. 消费以服务端事务为准；同一 operationId 重试返回同一结果，不重复扣减。
4. 同一跨学科成果在多个页面出现仍只有一个权威证据；分配展示不是再次奖励。
5. 教师撤回误判走撤销/补偿事件，旧记录保留；不得默默删除或让学生承担无法解释的负债。
6. 部分授权用途不同，UI 显示本动作实际可用量；碎片合并由服务端合法分配，不拿总余额承诺可操作。
7. 班级共建由小组成果和自愿装扮积分分别记账；不要求所有学生贡献相同数量，不按消费排名。

## 8. 证据链、逻辑链与数据链

```text
课程目标 objectiveId
  -> 任务 taskRunId / 项目 projectId
  -> 来源 sourceType + sourceId + sourceVersion
  -> 证据 evidenceId + revision + 内容哈希
  -> 评价 decisionId + rubricVersion + actor + feedback
  -> 成长投影 milestoneId / plotId
  -> 作品 artifactId -> 档案、徽章、班级授权展示
  -> 复习 reviewId -> 新证据（保留与原证据的关联）
```

### 8.1 三组状态不能互相替代

| 状态组 | 建议状态流 | 必须区分 |
| --- | --- | --- |
| 证据 | 草稿 -> 已提交 -> 待评价 -> 需修订 / 已接受 -> 被替代 / 被撤销 | 已提交不等于已接受；订正接受不等于独立掌握 |
| 一次任务 | 未开始 -> 进行中 -> 已保存待继续 / 待反馈 -> 本次完成 | 本次完成不等于长期复习已完成 |
| 操作请求 | 空闲 -> 提交中 -> 已确认 / 结果未知 / 失败 | 超时可能已提交，必须查操作状态再重试 |

庄园的视觉阶段来自服务器认定的里程碑，不由前端点击计数自行决定。作物生长是作品阶段的隐喻，不宣称真实植物生理过程；科学活动中的真实生长数据另有来源标记。

### 8.2 学生能读懂的来源卡

一张卡回答六个问题：我做了什么、属于哪个目标、原始材料在哪、谁按什么标准给了反馈、我改了什么、它为什么影响这块田。

默认展示“已保存草稿 / 已提交老师 / 需要补充 / 已入册”等自然语言。技术 ID 收在详情，不把审计字段堆给学生。记录不完整时显示“尚未关联来源”，不自动填造证据。

### 8.3 数据采集最小化

- 采集有教学目的的提交、修订、反馈、任务恢复、复习结果和故障事件；每类说明用途、查看角色和保留策略。
- 不把鼠标轨迹、每次按键、游戏在线时长、无操作停留、设备指纹作为学习能力标签。
- 不自动保存学生全部 AI 对话、所有 HTML 页面内容或浏览历史。学生选择引用材料后仍保留可见范围。
- HTML 活动通过受控桥接返回经 schema 校验的结果；客户端自报内容标记“待核验”，后端按会话、来源、版本和规则验证后才改变证据状态。
- 学生查看本人记录；教师仅访问被授权班级/任务；同学只看到已授权展示的作品摘要，不看到错题、私人反馈和积分详情。
- 学校调班、退学、转学和教师离职要有权限回收与导出策略；研发日志不保存原始敏感内容。

## 9. 入口与按钮闭环规格

以下是目标行为，不代表现有功能已接通。统一要求：可用、选中、提交中、成功、失败、无权限、条件不足均有明确状态；禁用时提供可达的原因说明。

| 入口 / 动作 | 打开什么或做什么 | 真实结果 | 失败 / 恢复 |
| --- | --- | --- | --- |
| 今日行动 | 恢复当前 taskRun | 显示目标、已保存步骤和下一步 | 无任务转教师已发布活动，不塞固定题凑数 |
| 开始 / 继续 | 创建或恢复同一任务运行 | 服务端 runId / revision | 请求未知先查询，不重复创建 |
| 查看土地 | 对象详情浮层 | plotId、作物、项目、来源、可执行动作 | 空地与锁地有不同原因与下一步 |
| 播种 | 选择可用外观作物及展示位置 | 服务端地块结果；学习任务可不种植照样完成 | 冲突刷新对象，保留用户选择 |
| 浇水 / 照料 | 仅作用于有待呈现成长的对象或纯外观反馈 | 展示已被认可的成长，不伪造新证据 | 尚无对应成果时链接该任务，不扣积分 |
| 原施肥 / 除虫 | 首期移除或改为有确切功能的“记录 / 修订”入口 | 分别打开记录与反馈流程 | 不保留有数量却没有库存契约的工具 |
| 收获 | 确认已达到可展示阶段的成果 | 仓库收藏或成果展示引用，不重复奖励 | 未就绪说明缺哪个阶段；不删除原证据 |
| 整理 / 移除作物 | 确认移除场景摆放 | 只改摆放，档案仍保留 | 确认框说明影响，提供允许范围内撤销 |
| 仓库 | 物品、作物收藏、装饰分类 | 数量、已摆放/未摆放、操作记录 | 空状态通向免费基础装饰或积分规则 |
| 装扮 | 选中物品 -> 预览 -> 保存 | 坐标、碰撞校验、布局 revision | 取消恢复原布局，保存冲突不覆盖他端 |
| 成果图鉴 | 按项目/目标/来源查看 | 每项展开证据与历史版本 | 没有成果则转继续任务，不展示虚构徽章 |
| 创作工坊 | 选择任务和来源，编辑解释/观察/作品 | 草稿保存、提交、修订各自有回执 | 字数/附件/权限错误保留输入；零积分可写作 |
| 记忆温室 | 到期/计划/完成三个视图 | 回忆作答、反馈、变式与再安排 | 允许合理延期，不扣荣誉、不枯萎 |
| 班级共建 | 展示共同目标与我的可选贡献 | 学习作品贡献和积分消费分列 | 零积分也能参与有意义的学习贡献 |
| 参观同学 | 切换为明确的访客只读视图 | 真实园主、授权作品、返回我的庄园 | 不存在/未开放给出原因，不改本人画布伪装参观 |
| 信箱 | 与当前学校消息体系联动 | 教师反馈、作品状态、深链 | 已读失败可重试，不永久写死“暂无消息” |
| 问题反馈 | 分类、描述、可选附件、隐私提示 | 工单编号/保存成功；后端未开则隐藏提交承诺 | 不自动上传账号、日志或全屏截图 |
| 结束 / 返回 | 保存草稿并回到学习中心 | 真实导航及保存状态 | 未提交操作先确认；退出不默认封禁到次日 |
| 同步状态 | 最近成功同步时间与待同步数量 | 查询操作最终状态 | 不把离线本地缓存显示成服务器已保存 |

基础只读/学习操作不应因为积分不足而不可用。“暂未开放”与“你没完成前置条件”严格区分，不能把产品缺功能归因到学生不够努力。

### 10.3 生图与切图流程

1. 先锁定风格板、视角、光源和 24 格几何，再生成可拆分环境与组件；不让每批资产自行改变透视。
2. 构图参考与生成文件分别登记。输出原创素材或具有明确使用范围的授权资产，参考文件不放入 `public`。
3. 绿幕仅作为生产母版选项。大量植物本身是绿色，普通色键会误删叶片；优先透明输出，或使用边界约束去底及人工边缘复核，必要时选择非主体颜色底。
4. 运行时使用去底后的透明 PNG/WebP，不直接显示绿底；原始高分辨率文件归档，按设备生成合理分辨率，不向所有学生发送 4K 图集。
5. 每项记录 assetId、来源/许可范围、生成模型和提示词摘要、版本、尺寸、哈希、锚点、可用路由；不记录 API 密钥或供应商令牌。
6. 检查透明边缘、白/深背景表现、同组光源、点击遮挡和小尺寸可读性；图集只分批少量同类物体，避免跨格污染。
7. 禁止把未生成成功的路径当已交付；缺图时有合适的基础图标和文字兜底。

示例生成要求：`原创校园农场观察工作台，斜向俯视，与既定木材/叶片材质和左上光源一致，完整物体和柔和落地阴影，无文字、无数字、无 Logo、无 UI 截图，独立背景，清楚轮廓，可在小尺寸辨认。`

## 11. 技术路线与接口补齐

### 11.1 不推翻现有工程

维持当前 Next.js / React / TypeScript 与服务端领域层。现有 manorV2 已有证据、授权、消费、地块、事件和操作幂等基础，应补齐边界，不重写成另一套 Unity 或桌面微端。

主场景先使用图片层 + DOM 热点 + 统一坐标；文字工作面保持 DOM。只有实际性能测量证明大量对象需要渲染引擎时，再单独评估，不为“看起来像游戏”增加引擎复杂度。

```text
ManorShell + SceneManifest + OverlayCoordinator
  -> TaskWorkspace / EvidenceDrawer / ReviewGreenhouse / Inventory
  -> 现有 HTTP Repository（补超时、查询、取消和错误状态）
  -> manor 领域服务 + 项目/资源/档案适配层
  -> 权威事务 / 事件 / 幂等操作 / 投影
  -> SQLite 校内单实例，或经过迁移验证的 PostgreSQL 多实例
```

### 11.2 API 状态清单

| 接口能力 | 当前情况 | 本期工作 |
| --- | --- | --- |
| `/api/v2/manor/bootstrap` | 存在 | 补任务运行、来源、年级策略和动作前置条件；分页避免全量作品增长拖慢首屏 |
| `/api/v2/manor/evidence` | 存在 | 学生 UI 接表达证据；明确规则/教师判定，不将自报结果直签掌握 |
| 教师 evidence / decisions | 存在 | 同版本审核、修订回流、学生收到反馈与深链 |
| plots/{id}/actions | 存在 | 统一对象版本、授权合法分配和真实工具语义 |
| reviews | 现有安排复习 | 增加到期查询、开始/提交/完成/延期，不只 schedule |
| artifacts | 存在 | 草稿与成果分态；保留反思；消除证据/授权错配与保存门槛 |
| task-runs / reflections | 需要补齐领域持久化 | 开始、保存、恢复、阶段完成及反思关联 |

| notifications / resources | 平台已有模块 | 先核实真实持久化和权限再接入，不能把前端原型当生产服务 |

所有新增地址只是候选契约，编码前需与已有路由命名对齐。一次成功回执至少包含 operationId、entityId、revision、stateVersion、结果状态与必要的最新快照；敏感教学内容按权限返回。

### 11.3 错误与异步策略

- 立即反馈已点击；短等待显示提交中；到达请求时限后显示结果未知/重试入口，时限按内网和公网实测调整，不写虚假百分比。
- GET 可有受限退避重试；写请求只使用同一 operationId 重试，冲突返回最新版本供用户确认。
- 禁止简单地把所有错误改成“服务不可用”；鉴权、权限、草稿校验、版本冲突、资源不足、只读会话和离线各自解释。
- 不设置“超时 = 自动回滚已提交结果”。先查操作，再决定展示或重试。
- 断网只能承诺本机保存草稿；待同步结果不能预发积分或显示教师已接受。

### 15.3 由实机结果修正的方案决策

1. **不能把参考账号的整屏状态做成庄园底图。** QQ 场景中当时可见的成熟作物、枯植株、锁和等级属于账号状态；EduAI 目前的静态底图却保留类似状态，叠上另一套真实地块。这正是 M01 的根本矛盾。环境只保留房屋、道路、天空等非业务背景；作物、土地状态、数字和标记单独渲染。
2. **木框负责归属感，正文负责学习。** 仓库和活动详情都提供大块相对干净的阅读面。学习任务不应满屏木纹、彩色标签和复杂卡片；纸面正文、附件和教师反馈采用稳定排版。
3. **学习状态与物品状态分仓。** 仓库的数量、分类和空态可迁移到种子/装饰，但学习成果要进入作品与证据索引。不能把“获得道具”“完成任务”“教师接受”画成同一个勾。
4. **给关闭、等待和失败同等设计权重。** 官方入口本轮也出现一次配置下载失败；学习平台须提供可理解的等待和恢复，不重复扣减、不丢草稿。仓库/活动的退出要回到原场景，不能只让弹窗消失而丢任务上下文。
5. **参考视觉，不复制 Canvas 的可访问性限制。** 本轮可访问树没有暴露游戏内仓库、图鉴等按钮的语义，只能按截图定位；这是观察，不是完整 WCAG 审计。EduAI 保持 DOM 按钮、可聚焦列表、可读状态和键盘等价操作，不因仿游戏而舍弃可访问性。
6. **主题活动必须围绕一个可检验的问题。** QQ 将周期、生产、订单和兑换围绕同一活动组织，结构上连贯；教育版对应共同问题、采集数据、提出解释、教师反馈和成果展示，不对应多学科贴标签及换代币。采用第 5 节“校园花圃怎样节水”作为首条完整示例。

这轮没有测量帧率、内存、加载时延分布或移动端 QQ 适配，也未核验其后台接口和奖励算法。上述参考足以校准设计方向，但仍需按第 14 节对 EduAI 自身完成实现后的真实验收。
