# Nunito Workspace -> EduAI Prism 教师端课件工坊迁移规格

状态：已实施并通过本地验收  
目标版本：courseware.v1  
来源基线：`D:\VB\LLM试点\release\Nunito Workspace 0.1.0.exe`

## 1. 迁移边界

本轮迁移 Nunito 中与 EduAI 现有能力不重复的课件工作流：

`填写教学简报 -> 引用校内资料 -> 生成逐页方案 -> 教师逐页审阅/订正 -> 服务端持久化 -> 下载可编辑 PPTX`

现有 AI 对话、提示词中心、知识库、文档解析、生图和管理端不复制；课件工坊直接复用这些服务的认证、上传解析、模型网关、配额与审计边界。

不迁移 Nunito 的桌面端登录、设备 MAC 标识、本地 10M 配额、打包密钥仓、固定会话密钥、超级管理员和用户管理。它们与学校平台现有的会话、RBAC 和服务端密钥管理冲突。

## 2. 必须满足的闭环

1. 教师或科研角色可从「教研 -> 课件工坊」进入；学生和管理角色不能调用课件 API。
2. 课件简报至少包含学科、年级、主题和 4-12 页页数；可附加最多三份已由 `/api/upload` 解析的校内文档。
3. 规划请求必须等待模型或诚实的本地结构模板返回后才显示成功；返回值标明 `remote`、`local` 或 `local-fallback`。
4. 每页均保存标题、教学意图、要点、版式、视觉建议和教师讲解提示；教师可逐页修改。
5. 修改采用 `stateVersion` 乐观锁，旧版本写入返回 409，并返回服务端权威版本。
6. 重复 `operationId` 且请求指纹一致时返回第一次的权威结果，不重复建课件或重复写入；同键不同内容返回 409。
   客户端对同一内容的失败重试复用原 `operationId`；服务端以租约令牌隔离陈旧工作者，并把业务写入与操作完成放在同一事务。
7. PPTX 由服务端生成，文字和形状保持原生可编辑；不把整页截图冒充可编辑课件。
8. 本地结构模板必须明确提示教师复核，不虚构教材事实、引用或统计数据。
9. 未保存内容在课件切换、站内链接、浏览器历史返回和关闭/刷新前均受到保护；版本冲突必须由教师明确选择保留本地或载入服务端。

## 3. API 契约

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/courseware` | 当前用户课件列表 |
| `POST` | `/api/courseware/plan` | 生成并持久化逐页方案 |
| `GET` | `/api/courseware/:id` | 读取一个课件 |
| `PATCH` | `/api/courseware/:id` | 按版本保存教师订正 |
| `GET` | `/api/courseware/:id/download` | 生成并下载可编辑 PPTX |

所有写操作都返回：`operationId`、`stateVersion`、`status`、`authoritativeEntity`、`nextActions`。所有列表与详情响应使用 `cache-control: no-store`。

## 4. 数据与安全

- 数据归属以会话 `user.id` 为唯一边界，SQL 查询始终带 `ownerId`。
- 上传资料通过既有 `getUploadsForUser` 再次做归属过滤；客户端提交别人的 upload id 不会进入模型上下文。
- 不引入新运行时密钥，不读取或迁移 Nunito 的 `desktop/key-vault.local.json`。
- 不引入 `pptxgenjs`。来源仓库的依赖审计显示其当前依赖链存在高危公告；本项目使用已有 `jszip` 生成受控 OOXML。
- 下载文件名经过清理；所有写入 OOXML 的文本都做 XML 转义，并移除 XML 1.0 禁止的控制字符。

- API 测试：鉴权/RBAC、真实持久化、请求指纹幂等、陈旧租约接管、旧令牌 fencing、并发请求、版本冲突、跨用户隔离、下载内容类型、备注关系与 ZIP 结构。
- 浏览器测试：390px 下的生成/保存响应丢失重试、站内链接与历史返回保护、版本冲突双分支、触控尺寸和横向溢出。
- Office 兼容性：Microsoft PowerPoint 实际打开 6 页成品，读取到 6 页、可编辑形状和中文教师备注，未触发修复提示。
- 工程门禁：TypeScript、ESLint、生产构建和独立只读 Agent 差异审阅。CodeRabbit CLI 已校验发行签名，但本机账户未授权，因此不计作通过证据。
