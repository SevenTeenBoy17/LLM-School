## 2. 能力拆解与迁移决策

### 已迁移

`教学简报 -> 校内资料 -> 结构化逐页规划 -> 教师逐页审阅 -> 版本化保存 -> 可编辑 PPTX`

- 教师可设置学科、年级、课题、4-12 页、学习目标、呈现风格与补充要求。
- 可引用最多三份当前教师账号拥有且已解析的校内文档。
- 在线模型返回不满足契约时，使用确定性本地结构方案并明确要求教师复核。
- 页面标题、教学意图、要点、版式、视觉建议、教师讲解提示与资料引用均可编辑。
- 服务器持久化课件，使用乐观锁处理多窗口修改冲突。
- 服务器生成原生文字和形状的 PPTX，并把教师讲解提示写入演讲者备注。

### 复用现有平台能力

- 会话与 RBAC：沿用 EduAI Prism 的 `getSessionUser`、角色导航和访问控制。
- 文件解析：沿用 `/api/upload` 与账号归属过滤。
- 模型调用：沿用服务端模型网关、超时、大小上限、出站地址检查和审计。
- 安全边界：沿用同源写请求保护、速率限制、演示账号只读和下载鉴权。

### 明确不迁移

- Nunito 桌面端登录、设备 MAC 标识、本地 10M 配额、超级管理员和用户管理。
- 来源密钥仓、固定会话密钥、任何明文或打包密钥。
- 与 EduAI 已有 AI 对话、提示词、知识库、生图和管理能力重复的页面。
- 来源 `pptxgenjs` 运行时依赖。固定版本验证时发现其依赖链仍有两项高危拒绝服务公告，已回滚安装；目标项目生产依赖审计保持 0 漏洞。

## 4. 后端与数据闭环

| 方法 | 路径 | 权威结果 |
| --- | --- | --- |
| `GET` | `/api/courseware` | 当前账号课件列表 |
| `POST` | `/api/courseware/plan` | 已持久化的逐页方案 |
| `GET` | `/api/courseware/:id` | 当前账号拥有的单个课件 |
| `PATCH` | `/api/courseware/:id` | 新 `stateVersion` 与服务端权威实体 |
| `GET` | `/api/courseware/:id/download` | 服务端生成的可编辑 PPTX |

服务端按需建立 `courseware_decks` 与 `courseware_operations`。所有课件读取和写入均带 `ownerId`；上传资料再次按 `user.id` 过滤。写操作以 SHA-256 请求指纹绑定 `operationId`：完全相同的重放返回首次结果，不同请求复用同一键返回 `409 IDEMPOTENCY_CONFLICT`。客户端对同一内容的网络失败重试复用原键；服务端以租约令牌隔离陈旧工作者，并在一个 `BEGIN IMMEDIATE` 事务内提交业务实体与操作结果。旧版本保存返回 `409 VERSION_CONFLICT` 和服务端权威实体。

## 5. 输出文件兼容性

PPTX 由现有 `jszip` 生成受控 PresentationML，不依赖来源项目包。输出包含：

- 标准内容类型、主文档关系、视图属性、母版、布局和三项主题样式矩阵。
- 每页独立、可编辑的原生文字框与形状。
- 每页教师讲解提示对应的 notes slide、notes master 与双向关系。
- 用户内容 XML 转义和安全文件名。

除 ZIP/XML 断言外，成品已由本机 Microsoft PowerPoint 无修复提示打开：识别 6 页，首页 4 个可编辑形状，并读回中文教师备注。

## 7. 部署注意事项

- 生产环境必须配置独立 `SESSION_SECRET` 和服务端模型密钥；任何密钥都不得进入浏览器包或仓库。
- SQLite 适合单机学校服务器部署；多实例互联网部署前应把课件表迁移到共享数据库，同时保留 `ownerId`、唯一幂等键和 `stateVersion` 约束。
- 课件内容仍需教师复核后用于课堂；在线模型输出不会被标记为教材权威事实。
- 来源项目保持只读且存在未提交文件，本次迁移未修改或清理来源工作区。
